# 引き算幻獣ハンター：バトル演出の実装方針

更新日：2026-10-03。移植元は [keisan の完成コミット 92f4d85](https://github.com/yggdrasilw-spec/keisan/commit/92f4d85)。この方針に基づいて引き算側へ実装。接続方法・素材・検証結果は [実装記録](battle-animation-implementation.md) に記載する。

## 基本方針

足し算忍者のバトル演出を土台に、学習画面の両端でハンターと幻獣が戦う。**相手は、そのコースを達成すると手に入るバッジ／メダルの幻獣**とする。既存の報酬画像の姿・色・正式名に合わせ、無関係な敵をランダムに出さない。獲得済みでも同じ幻獣と再戦する。

採点、問題数、制限時間、マスター判定、報酬、解放条件は変えない。通常練習は誤答を含んでも完走で勝利を見せるが、メダル付与は従来の条件を満たしたときだけ行う。撃破だけで新しい報酬を付与したり、再戦で重複付与したりしない。達成時は幻獣が光になり、仲間になることが伝わる演出にする。血や残酷な表現は使わない。

## 敵と報酬の対応

実際の入口は `hikizan_hunter.html`。通常報酬はその中の `ACH_BADGE_DEFS`、コツは `KOTSU_IMG_DEFS`、正式名は `js/hunter-creatures.js` を参照する。残っている `js/09-achievement-data.js` の足し算由来の定義を採用しない。

| コース | 報酬キー | 相手の幻獣 | 参照画像 |
| --- | --- | --- | --- |
| くりさがりなし・20問 | easy_20 | ユニコーン | img/medal_easy20.png |
| くりさがりなし・すべて | easy_all | ヨルムンガンド | img/medal_easy_all.png |
| 10からひく・すべて | ten_all | マンティコア | img/medal_ten_all.png |
| くりさがりあり・20問 | hard_20 | アジ・ダハーカ（光） | img/medal_hard20.png |
| くりさがりあり・すべて | hard_all | アジ・ダハーカ（闇） | img/medal_hard_all.png |
| ばらばら・20問 | mix_20 | プリズム・スタッグ | img/medal_mix20.png |
| ばらばら・すべて | mix_all | アストラル・ドラゴン | img/medal_mix_all.png |

コツは選択した `kind`・`axis`・`num` から報酬キーを決め、35枚それぞれの幻獣に接続する。画像は既存の `kotsuImgSrc(def)` と `def.file`、名前は `hunterCreatureName(def)` を使う。コツでも師範へ置き換えず、対応する幻獣が達成を認める動作を見せる。

神速・超神速は `js/hunter-speed-badges.js` の定義を使う。

| コース | 神速：報酬キー／幻獣 | 超神速：報酬キー／幻獣 |
| --- | --- | --- |
| no | no_shinsoku／風渡りの銀狼 | no_super／蒼星の角鹿 |
| ten | ten_shinsoku／十灯の星蛾 | ten_super／金環の砂漠狐 |
| borrow | borrow_shinsoku／雷角の岩獅子 | borrow_super／紅蓮の双翼竜 |
| mix | mix_shinsoku／瞬虹の空鯨 | mix_super／天球の星海蛇 |

画像は `img/badge_<course>_<tier>.png`。実装上の超神速キーは `super` であり、足し算の名前をそのまま流用しない。

直接対応する報酬がない練習は、次の既定で進める。新しい獲得条件は設けない。

- にがて：選択コースの20問の幻獣。10からひくは `ten_all`。
- 無限：選択コースに属する既存の幻獣から遭遇表を作る。5正解で1体、16〜20問は同コースの上位幻獣、20問ごとに繰り返す。無限自体の新規バッジは追加しない。
- 対応キーを特定できない画面：学習を続け、演出は非表示。別コースの幻獣を勝手に割り当てない。

## 足し算版から引き継ぐ仕様

- 横長画面の両端のみ。幅960px以上・高さ540px以上・縦横比4:3より横長を候補に、式・回答・ヒントとの実寸の重なりを確認する。中央の教材や入力の寸法を保つ。
- 正解で攻撃、3連続・5連続で技を強める。誤答で連続数をリセットする。ハンターの装備に合わせて技の絵を置き換え、連続技のための新しい学習ルールは作らない。
- 通常コースは実際の問題数に合わせた進行。神速・超神速は短い反応、完走で勝利、誤答・時間切れ・途中終了で撤退。無限の未完了の相手を撃破数に含めない。
- 終了演出は通常約1.4秒、スキップ可能。オフ・非表示・通常の途中終了では結果を待たせない。画面移動後に古い結果を出さない。
- 通常・ひかえめ・オフ、OSの動きを減らす設定、ヒント・暗唱・画面非表示での停止、隠れた間の攻撃を再生しない仕様を維持する。
- 描画・PNG読み込み失敗でも学習を継続する。演出を入力・読み上げ対象にしない。戦闘音は追加しない。

## 素材と成長

画像生成した透過PNGのスプライトシートで管理する。ハンター4段階は既存の `img/genju_hunter_lv1.png`〜`lv4.png`、幻獣は対応するメダル画像を参照して新規生成する。元の図鑑・報酬画像は上書きしない。通常7体→挑戦8体→コツ35体の順で増やし、最終的には50体すべての報酬に対応する。

足し算版と同じ4列、主人公7行・敵5行を基本にし、待機・攻撃・被弾・達成・退場を表現する。大きな角・翼・尾を含めてセル内に収め、最近傍描画、足元の統一、プレビューと生成プロンプト記録を引き継ぐ。幻獣の体形に応じて表示寸法を調整し、式や入力へはみ出さない。

足し算版では生成画像のコマが等間隔にならず、均等分割で刀・手裏剣・足先が欠けたため、透明な隙間に沿う切り出しへ修正した。[切り出し修正コミット 0614c74](https://github.com/yggdrasilw-spec/keisan/commit/0614c74) まで含めて移植する。幻獣でも元画像の全不透明画素の保持、角・翼・尾・飛び道具のコマ所属、全コマ一覧の目視まで検証し、正規化後だけのテストで済ませない。

成長判定は引き算の `ACH_STAGES`（実績数0・8・18・28）を参照する。足し算の忍者画像や成長閾値へ置き換えない。演出設定・保存・バックアップは引き算の既存設定へ接続し、足し算の保存キーを共有しない。

## 実装の手順と注意点

1. `keisan/docs/battle-animation-implementation.md` と `js/21-battle-art.js`、`js/22-battle.js`、`css/10-battle.css` を確認する。確定した足し算コミットを起点にする。
2. 引き算専用の報酬キー→参照画像→幻獣名→スプライトの対応表を用意し、上のコース対応をテストする。
3. `hikizan_hunter.html` の開始・出題・回答・終了・画面移動に接続する。`hunter-challenges.js`、`hunter-flow.js`、`hunter-progression.js` の既存ラッパーと順序を確認する。挑戦モードは独自の回答／終了処理があるため通常だけのフックでは不足する。
4. 終了演出の前に時計と次問予約を止める。通常と挑戦の報酬キューをそれぞれ一度だけ実行し、既存の結果→報酬→進化を維持する。
5. 現在存在する学習画面だけに接続する。足し算の基礎iframeを新設する必要はない。0の答え、10からひく、繰り下がり、ドット／そろばんのヒントを保持する。
6. 素材プレビュー・実装記録・検証結果をMarkdownに残す。

## 完了条件

足し算のバトルテストを引き算のセッション構造へ移植し、4横長寸法×3入力方式、ヒント2種、縦画面非表示、連続技・誤答・手書き再入力・重複回答・途中終了・スキップ・画面移動・設定保存・PNG失敗を確認する。通常・コツ・神速・超神速の相手が対応バッジと一致し、獲得済みでも再戦できることを確認する。

通常の完走とメダル条件未達、条件達成時の一度だけの報酬、無限の5問／20問周期、失敗時の未撃破除外、挑戦記録と通常成績の分離、成長4段階を確認する。既存 `node tests/run.cjs` の学習・進化・ヒント・レイド・移行・挑戦・配置テストも実行する。
